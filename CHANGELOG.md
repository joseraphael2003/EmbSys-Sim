# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0] - 2026-10-04

Migrated the simulator substrate from Mbed OS 5.10.2 to **Mbed CE** (the Mbed OS 6
continuation), restored the TLS demos, added virtual board profiles, and rebuilt
CI around a cold-checkout path.

### Added
- **Pinned Mbed CE dependency closure (`build-tools/fetch-deps.js`):** fetches `mbed-ce/mbed-os@6886b0f` plus `mbed-http`, `simple-mbed-cloud-client` and the two CMSIS submodules, applies `patches/`, and verifies both the mbed-os component closure and the 26 files of the vendored `TARGET_SIMULATOR` target on every run (fresh fetch and fast no-op alike). An orphan-patch check fails if a patch in `patches/` matches no resolved dependency.
- **Positive component build graph (`build-tools/build-libmbed.js`):** an explicit 26-component manifest replaces the negative `.simignore` regex walk; `libmbed.a` is 408 objects, rebuilt from a fresh cache in ~100 s at `CONCURRENCY=3`. Cache invalidation is keyed on the ordered compiler-flag list, the two configuration headers and each object's `-MMD` header set.
- **Authenticated in-Wasm TLS with real entropy:** `mbedtls_hardware_poll` is bound to `window.crypto.getRandomValues()`; `MBEDTLS_TEST_NULL_ENTROPY` and `MBEDTLS_NO_DEFAULT_ENTROPY_SOURCES` are gone from both build pipelines. Untrusted issuers and host-name mismatches are rejected with `NSAPI_ERROR_AUTH_FAILURE` (-3011), asserted from both the client and the server side by `test/run-t4-tls.js` (12/12) and `test/run-t6-tls-demos.js` (11/11) against local servers and pinned certificates.
- **Virtual board profiles (`profiles/boards.json`):** Raspberry Pi Pico (RP2040) and ST Nucleo-F401RE alongside the default LPC1768-style board, with vendored Fritzing/Raspberry Pi vector assets, `ATTRIBUTION.md`, and `--board <name>` on `cli.js` and the viewer. `PinNames.h` and `viewer/js-hal/pinnames.js` are generated from the one descriptor by `build-tools/generate-pinnames.js`; `--check` fails on drift (including CRLF drift on a Windows checkout). `build-demos.js` also builds a per-board preview of the default demo (`out/blinky-pico.js`, `out/blinky-nucleo.js` - the board list comes from `profiles/boards.json`, the demo from `demos/simconfig.json`, and the previews are counted separately from the 21 demos), which is what the editor page loads when a board is selected: the drawing then matches the compiled binary and the onboard LED runs before the first Run, instead of the default board plus a "requested board ignored" warning.
- **Link-closure artifact gate (`build-tools/scan-unresolved-imports.js`):** scans every built demo for Emscripten's `missing function:` import stubs and fails the build if any exist. All 21 demos scan clean.
- **OS5 to OS6 migration guide (`docs/OS5_TO_OS6_MIGRATION_GUIDE.md`):** before/after pairs for the APIs the coursework uses (`wait_ms`/`wait`, `wait_us`, `Timer::read`/`read_ms`, `Ticker`/`Timeout::attach` float seconds, `Serial`/`RawSerial`, `EventQueue::dispatch`), each compiled in both directions against this repository, with the exact diagnostic the old form produces.

### Changed
- **CI (`.github/workflows/ci.yml`):** triggers on `modernization-plan2`; builds the Docker image (dependency fetch, `libmbed.a`, 21 demos plus per-board previews of the default demo), then re-runs each gate as its own container step - dependency-closure guards, `generate-pinnames --check`, the 21-demo suite, the artifact scan, the relay pre-subscribe controls, the `blinky` scenario, the two TLS harnesses, `blinky` smoke scenarios on the `pico` and `nucleo` boards, a viewer harness that drives the board profiles, the `?board=` XSS PoCs and the rule that the drawing follows the compiled binary, and a serial gate that builds and runs `test/fixtures/test-serial` (`UnbufferedSerial pc(USBTX, USBRX)`) on all three boards - the only artifact whose link closure covers `core_util_in_critical_section`, which no demo reaches. Public-internet demo scenarios moved to a separate scheduled job so a third party's downtime or certificate rotation cannot fail a push. Validated on GitHub Actions: run `39175465664` on `c4cca29` is green - job `Build & Headless Smoke (hermetic)`, 7m34s, every gating step listed above - with the public-internet `network` job scheduled-only by design. Each gate was also replayed from a fresh clone on a cold `--no-cache` image before it was pushed.
- **Docker image:** now fetches the pinned dependencies before building (`RUN node build-tools/fetch-deps.js`), installs Node dependencies in their own layer, and excludes host build products (`.obj/`, `libmbed.a`, `out/`, the fetched checkouts) from the build context. A cold `docker build` finishes the full 21-demo suite.
- **All 21 demos** build with zero exclusions: `bd`, `blinky`, `busout`, `coap`, `events`, `http`, `https`, `interrupts`, `lcd`, `lorawan`, `lorawan-abp`, `ntp`, `peliondm`, `pwm-speaker`, `pwmout`, `tcpsocket`, `tcpsocket-async`, `temperature`, `tlssocket`, `touchscreen`, `trace`.
- **README:** documents `CONCURRENCY`, the headless-run browser prerequisites (Chromium shared libraries plus `npx puppeteer browsers install chrome`), the `test/` harnesses, the CI layout and the migration guide.

### Fixed
- **Default builds recorded no board in their manifest.** `--board` was only resolved when it was given, so `.components` carried `"board": null` for every artifact `build-demos.js` produced, and the viewer read that as "no board recorded" and honoured `?board=`. `/view/blinky?board=pico` therefore drew a Pico over a wasm binary compiled for the default board: the wrong pin map for the program, a dead LED and no warning (the exact case the manifest was supposed to prevent). `cli.js` now resolves the default descriptor, `build-application.js` records the board id for every path (`"default"` included), and the viewer always draws the board of the binary - a manifest without the key is read as `default` (that is the enum it was compiled against), and a conflicting `?board=` is ignored and reported with a visible mismatch banner instead of the wrong drawing.
- **The TCP relay dropped bytes that arrived before the browser subscribed.** `socket_open` subscribes over socket.io while `socket_connect` dials over a separate blocking request, so a peer's first flight could reach the relay before the subscribe frame; those bytes were discarded, which stalled the in-Wasm TLS handshake whenever the subscribe lost the race (measured: `test/run-t4-tls.js` failed 4-5 runs in 6 before the fix, 10 in 10 after). The relay now buffers pre-subscribe data per socket and flushes it in order on subscribe, and replays a terminal event that was decided before anyone subscribed. More than 1 MiB of unsubscribed data closes the connection with an error delivered to the application rather than silently dropping bytes. `test/run-t10-relay-controls.js` forces the pre-subscribe window deterministically and fails against the old relay.
- **`node cli.js` on a fresh checkout:** the component manifest was validated at module load, before `fetch-deps.js` could run, so every cold tree - including `docker build` and the documented from-source install - failed with `the component manifest declares N path(s) that do not exist`. Validation now runs inside the build, after the dependency fetch.
- **`cli.js -o out` on a fresh checkout:** the output directory is created when missing and an existing regular file in the way is a hard error (previously it wrote a file named `out` and every scenario 404'd).
- **`UnbufferedSerial` and `BufferedSerial` could not run in an application.** `core_util_in_critical_section()` - called by `mbed-os/drivers/source/UnbufferedSerial.cpp:50` and `BufferedSerial.cpp:159`, asserted by `hal/source/LowPowerTickerWrapper.cpp` - is defined in `mbed-os/platform/source/mbed_critical.c`, which is not in the component manifest, so `libmbed.a` carried three references to a symbol nothing defined. No demo noticed (none of the 21 uses `UnbufferedSerial`), but the first application that does links with an unresolved import and the runtime refuses to start it (`Link closure incomplete: 1 unresolved symbol(s): core_util_in_critical_section`). The function is now defined in the simulator's own critical-section seam (`targets/TARGET_SIMULATOR/platform/mbed_critical.cpp`), which already owns the `core_util_*` no-ops and the PRIMASK trio for wasm, and `core_util_critical_section_enter`/`exit` count nesting instead of being empty, so the answer covers CE's own callers as well as callers that set PRIMASK themselves (update-client-hub's atomic queue). Nothing masks interrupts: the substrate is single-threaded and cooperative.
- **`USBTX`/`USBRX` now compile in application code on the default board.** Mbed CE's `hal/PinNameAliases.h` does `#define USBTX CONSOLE_TX` unconditionally, so `UnbufferedSerial pc(USBTX, USBRX)` expanded to `CONSOLE_TX`/`CONSOLE_RX`, which the default board's pin table did not declare (`error: unknown type name 'CONSOLE_TX'`, note: expanded from macro `USBTX`). The default board's console pads are now named `CONSOLE_TX`/`CONSOLE_RX` on the pads they have always used (`P0_2`/`P0_3`) - the same names Mbed CE's own MBED_LPC1768 target and the `pico`/`nucleo` profiles use - and `USBTX`/`USBRX` keep resolving to those values through the alias macro. They are gone as *enumerators*: declaring `USBTX` beside `CONSOLE_TX` is a duplicate-enumerator error in `hal/source/static_pinmap.cpp`, whose `hal/static_pinmap.h` includes the alias header before `PinNames.h`. Measured: `UnbufferedSerial pc(USBTX, USBRX)` compiles and links on all three boards, and every other pre-fix pin name keeps its value.

### Removed
- **The Plan 1 demo exclusion list.** `https` and `tlssocket` are no longer excluded from `build-demos.js`: both compile and pass their scenarios with authenticated TLS. The 0.1.0 entry below records the exclusion as it was for that release.
- The `.simignore` negative-discovery mechanism (replaced by the component manifest) and the OS5-era null-entropy flags (`MBEDTLS_TEST_NULL_ENTROPY`, `MBEDTLS_NO_DEFAULT_ENTROPY_SOURCES`).
- `mbed-simulator-hal/mcc/mbed_shared_queues.cpp`, which the component manifest never built: it defined `mbed_event_queue()`/`mbed_highprio_event_queue()`, which `mbed-os/events/source/mbed_shared_queues.cpp` (component `mbed-os:events`) defines in the same closure. Listing it would have been a duplicate symbol.

### Security
- **Reflected DOM XSS through `?board=` on `/view/<demo>`.** The viewer's board id was interpolated into an inline script as a JavaScript string literal (`window.requestedBoard = "{{requestedBoard}}"`). HTML escaping is not string-literal escaping - hbs escapes `&<>"'` but leaves backslash alone - so `?board=%5Cu003cimg%20src%5Cu003dx%20onerror%5Cu003dalert(1)%5Cu003e` arrived as the literal characters `\u003c…`, the JS parser decoded them into an `<img onerror=…>`, and the board notice assigned the result to `innerHTML`. The whole class is closed, not the one sink: the server never renders a raw query value (it renders an allowlisted board id, or an unknown-board flag plus a bounded, control-stripped string), the viewer's configuration is embedded as JSON with `<`, `>`, `&` and U+2028/2029 escaped (`jsonForScript`), the board notice is built from DOM nodes and `textContent` instead of `innerHTML`, the `svgAsset` attribute is no longer unescaped, and the parent page's `knownBoards` lookups are own-property checks (`constructor`/`__proto__` no longer pass as board names). `test/test-t9-boards.js` runs both PoCs (the `\u003c` escape and a plain `<img onerror>`) plus a `constructor` board id, asserts that no element is injected and no dialog fires, and that the notice shows the payload literally. Measured: the PoC is EXPLOITED against 2034d96 (an `<img onerror>` element injected into the notice, a dialog fired, `window.requestedBoard` decoded back to markup) and the harness fails (5 checks, exit 1) when the pre-fix `innerHTML` sink is mounted over `viewer/js-ui/board.js`, while the same harness passes on the fixed tree (82 checks, exit 0).

## [0.1.0] - 2026-08-22

### Added
- **Node Dependency Fetcher (`build-tools/fetch-deps.js`):** Pinned, recursive `.lib` resolution using shallow Git fetches by SHA, completely eliminating Python 2.7, `mbed-cli`, and Mercurial from the build pipeline.
- **Upstream Emscripten Toolchain:** Dockerfile migrated to single-stage `emscripten/emsdk:3.1.74` image bundling Node >=18, Clang 20, and modern `emcc`/`emar`.
- **Static Library Archiving:** Transitioned `libmbed` compilation from single monolithic `.bc` to `libmbed.a` static archive created via `emar rcs` with persistent incremental `.obj` caching.
- **Whole-Program ASYNCIFY:** Blanket `-sASYNCIFY=1` on link ensures non-blocking browser event loop during Mbed OS `wait_ms` / `ThisThread::sleep_for` calls.
- **Serial Monitor Toolbar:** Added Clear, Download log, and Copy buttons above the xterm terminal pane in `viewer/viewer.html`.
- **URL-Shareable Labs (`#lab=`):** Added base64url URL hash encoding/decoding on `viewer/simulator.html` to share custom C++ code and peripheral models with inline oversize guards.
- **Headless Assertion Runner:** Added `--scenario <file>` JSON DSL runner in `cli.js` with proof scenario `scenarios/blinky.json`.
- **GitHub Actions CI:** Added `.github/workflows/ci.yml` building the Docker image and running golden suite smoke tests on push/PR.

### Changed
- Repointed `mbed-simulator-hal/mbed-os.lib` to upstream `ARMmbed/mbed-os@3b71b16` (verified byte-identical).
- Upgraded `socket.io` to v4 (`^4.8.1`) and `puppeteer` to stable (`^23.11.1`).
- Added `"engines": { "node": ">=18" }` to `package.json`.
- Updated `build-demos.js` with awaited sequential execution, strict exit codes, and principled exclusion list (`https`, `tlssocket`).
- Updated `viewer/js-ui/init.js` execution start signal to `Module.onRuntimeInitialized`.

### Fixed
- Fixed Node 22 deprecation warnings (`new Buffer()` -> `Buffer.from()`, `fs.exists` -> `fs.promises.access`).
- Patched `TARGET_SIMULATOR` headers and added `-include emscripten.h` in `build-tools/helpers.js` to defeat third-party `extern "C"` template errors under modern Clang.
- Corrected `simple-mbed-cloud-client/mbed-cloud-client(-1)?/` patterns in `mbed-simulator-hal/.simignore` to filter out non-simulator FreeRTOS/Linux BSP files.
- Removed legacy `.js.mem` routes from `server/launch-server.js` and verified `application/wasm` MIME serving.

### Removed
- Legacy fastcomp `EMTERPRETIFY` and `EMTERPRETIFY_ASYNC` compiler flags and CLI options.
- Python 2.7, `pip`, `mbed-cli`, Mercurial, and Debian Stretch archive apt hacks.
